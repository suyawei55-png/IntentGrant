# Contributing to IntentGrant

Thank you for reviewing and contributing to the IntentGrant protocol family —
the Core Specification, the IG-Lite Consumer Profile, and future profiles.

## Ways to contribute

1. **Issues (preferred for feedback)** — normative questions, errata, ambiguities,
   interop concerns. Reference the section number (e.g., IG-Lite v0.2 §4.7).
2. **Pull requests** — editorial fixes and clarifications are welcome. Changes to
   normative semantics (MUST/SHOULD/MAY requirements, field definitions, liability
   chain rules) are accepted through the maintainers' review, with rationale recorded
   in the issue thread before merge.

## Language

The normative specifications are authored in **Chinese**; the repository-level
documents (README, NOTICE, IP-STATEMENT, release notes) are in **English** for
international review. Issues and PRs are welcome in either language; the maintainers
will keep a bilingual summary in cross-language threads.

## Developer Certificate of Origin (DCO)

All contributions are made under **Apache License 2.0, inbound = outbound**.

Each commit must be signed off to certify that you have the right to submit it
under Apache-2.0 (Developer Certificate of Origin, https://developercertificate.org/):

```
git commit -s -m "Your commit message"
```

The sign-off line (`Signed-off-by: Name <email>`) must match the commit author.

## Licensing of contributions

By submitting a contribution, you agree that:

- it is licensed under Apache-2.0 as part of this repository (see [IP-STATEMENT.md](IP-STATEMENT.md));
- you grant the Apache-2.0 §3 patent license to the extent of your contribution;
- you have not embedded third-party material with incompatible terms, and any
  quotation from statutes, court decisions, or standards carries a verifiable public
  source citation (per the Specifications' own citation rules, e.g., IG-Lite §6.4).

## Scope note

Please do not open issues to request hardware designs, firmware, production
deployment parameters, or reference-implementation source code — see
[IP-STATEMENT.md](IP-STATEMENT.md) §4–§5 for what this repository does and does not
cover. Discussions on protocol semantics are always in scope.
